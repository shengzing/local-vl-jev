# 校准与评估

## 概率 ≠ 准确率

VLM 返回 `invoice: 0.89`，意思是"在这四个选项中，invoice 占据了 89% 的概率质量"。

**这不等于模型有 89% 的概率是对的。**

## 校准流程

### 1. 收集标注数据

准备 100-200 张已标注的图片（图片 + 正确答案）。

### 2. 运行打分

对每张图片运行打分，记录 top-1 答案和概率。

### 3. 计算实际准确率

```
实际准确率 = 正确预测数 / 总预测数
```

### 4. 概率 → 实际准确率映射

| 模型概率区间 | 实际准确率 | 含义 |
|-------------|----------|------|
| 0.90-1.00 | ? | 模型非常确信时，实际命中率 |
| 0.70-0.89 | ? | 模型比较确信时 |
| 0.50-0.69 | ? | 模型不确定时 |

### 5. 设定阈值

```python
THRESHOLD_AUTO = 0.85   # 自动处理
THRESHOLD_REVIEW = 0.60 # 人工复核
# 60% 以下 → 拒绝或升级
```

## 视觉模型的特殊校准问题

### 1. 图片质量影响

- 分辨率太低 → 模型可能"看不到"关键信息
- 模糊/遮挡 → 置信度虚高
- 建议：在校准数据集中包含不同质量的图片

### 2. 候选选项设计

- 选项太少 → 兜底选项 `OTHER` 被过度使用
- 选项语义重叠 → 概率分散在相近选项间
- 建议：每个选项应映射到不同的下游操作

### 3. 4bit 量化影响

4bit 量化可能影响 logit 的精度。如果两个选项的 logit 差距很小（<1.0），4bit 下可能持平。如果需要更高精度，用 8bit 模型。

## 局限性

### 本项目复现了什么

- Jev 式视觉推理路径（图片 → logits → 受限 softmax → 分布）
- 基于 mlx-vlm 的实现
- 打分 vs 生成的延迟对比

### 本项目没有复现什么

- **训练/校准**：Jev 的训练和校准工作
- **多图推理**：当前只支持单图输入
- **视频打分**：不支持视频帧序列
- **区域打分**：不支持对图片中特定区域打分

## 何时视觉打分不够

- 需要描述图片内容 → 用生成
- 需要检测目标位置 → 用生成（输出坐标）
- 需要阅读图片中的文字 → 用生成（OCR）
- 候选答案无法事先枚举 → 用生成
